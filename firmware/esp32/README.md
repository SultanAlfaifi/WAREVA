# متحكم الأمان ESP32

كل ثانية: يقرأ الحساسات، ويقرر بقواعد [`safety.h`](include/safety.h)، ويشغّل مرحّل الصمام ومرحّل مضخة الري، ويطبع سطر JSON للبوابة. القرار لا يعتمد على Raspberry Pi ولا على الشبكة.

## الملفات

| الملف | المحتوى |
|---|---|
| `include/safety.h` | متحكم الأمان، نفس خوارزمية `core/decide.py`، بلا اعتماد على Arduino |
| `include/rules.h` | الحدود، مولّدة من `core/rules.json`. لا تعدّلها يدويًا |
| `include/calibration.h` | توزيع الأطراف ومعاملات المعايرة. قيم بدء تُستبدل بالمعايرة الفعلية |
| `src/main.cpp` | البرنامج: القراءة والقرار والمرحّلات وسطر JSON وwatchdog |
| `test/test_safety.cpp` | يشغّل حالات `core/vectors.json` على الحاسوب |

## سلوك الأمان في العتاد

- المرحّلات مطفأة عند الإقلاع وعند إعادة التشغيل، فيبقى الصمام المغلق افتراضيًا مغلقًا.
- watchdog بمهلة 5 ثوانٍ يعيد تشغيل اللوحة إذا علق البرنامج، فينغلق الصمام.
- قراءة خارج المدى الكهربائي للحساس تُعامل كقراءة مفقودة، فيُحتجز الماء.
- أثناء حركة الصمام يُحتفظ بآخر موضع مؤكد حتى 5 ثوانٍ. بعدها، أو إذا نشط المفتاحان معًا، يصبح الموضع مجهولًا ويُحتجز الماء.
- إعادة الضبط بعد عطل الصمام بزر على الجهاز فقط، لا عن بعد.

## البناء والاختبار

```sh
python -m core.gen_rules_h          # من جذر المستودع، بعد أي تغيير في rules.json أو vectors.json
pio run -t upload                   # من هذا المجلد، لبناء البرنامج ورفعه
pio device monitor                  # لمشاهدة الأسطر
g++ -std=c++17 -Iinclude -Itest test/test_safety.cpp -o test_safety && ./test_safety
```

اختبار `test_safety.cpp` يمرّ بكل الحالات (48 خطوة). بناء `main.cpp` للوحة ESP32 لم يُجرَّب بعد على هذا الجهاز؛ يبنيه CI بـ PlatformIO.
